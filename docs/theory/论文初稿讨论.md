# P2 论文初稿讨论：领域语义变异算子的理论立场与空缺

## 1. 基本立场

P2 的核心不应是传统意义上的编程语言 mutation testing，而应是面向科学计算软件的 **Domain-Semantic Mutation Operators**。

基本判断：

1. 科学计算软件中的关键故障高度依赖应用领域；
2. 蜕变测试中的 MR 约束的是物理、数学与数值行为；
3. 因此，用于评估 MR adequacy 的变异算子应优先定义在领域语义层，而不是语法或句法层。

建议写入论文的核心句：

> For scientific computing software, metamorphic testing adequacy should be evaluated against domain-semantic mutants rather than language-syntactic mutants, because MRs specify semantic relations over physical, numerical, or mathematical behavior.

中文表述：

> 科学计算软件中的 MR 约束的是物理、数学和数值行为，因此用于评估 MR 充分性的变异也必须作用在领域语义层，而不是停留在编程语言语法层。

这并不意味着语法变异无用。更准确的边界是：

1. 语法变异主要评估代码级测试套件 adequacy；
2. 领域语义变异主要评估 MR 集合对科学计算行为约束的 adequacy；
3. 两者目标不同，可以互补，但 P2 的理论焦点应放在后者。

## 2. 为什么应用领域是必要维度

科学计算软件中的有效故障往往不是通用语法错误，而是领域语义错误，例如：

1. 物理常数、单位换算、归一化因子错误；
2. 边界条件、初始条件、源项、截面数据使用错误；
3. 网格、步长、收敛阈值、迭代终止准则错误；
4. 耦合变量传递错误；
5. 高/低保真模型关系被破坏。

这些故障不只依赖编程语言，而依赖物理模型、数值方法、输入参数、输出物理量和工程假设。

因此，P2 若仍按传统语法算子组织，例如 `+` 改 `-`、`<` 改 `<=`、删除语句，会削弱理论贡献，也无法支撑未来 MT 统一理论。

## 3. 受约束的通用性

Domain-Semantic Mutation Operators 必须具备一定通用性，否则它们只能是案例工程经验，不能支撑理论。

但这里的通用性不是跨所有领域的完全通用算子。合理目标是：

> 在同一语义失效类型上通用，在具体领域实例化时可变。

换言之：

```text
抽象语义算子通用 -> 领域参数化实例具体化
```

建议采用两层算子体系。

### 3.1 第一层：抽象语义变异类别

这些类别跨科学计算子领域共享，对应 P1-P5 元模式：

| 抽象算子 | 对应语义失效 | 对应元模式 |
|---|---|---|
| `mu_C` | Conservation-breaking | P1 守恒性 |
| `mu_M` | Monotonicity-breaking | P2 单调性 |
| `mu_G` | Convergence-breaking | P3 收敛性 |
| `mu_T` | Trajectory-distorting | P4 轨迹性 |
| `mu_F` | Fidelity-order-breaking | P5 偏序性 |

### 3.2 第二层：领域实例化规则

抽象算子必须通过领域模型实例化：

```text
mu_C(domain model, conserved quantity, tolerance, injection site)
mu_M(input parameter, expected direction, output quantity, valid range)
mu_G(refinement variable, convergence metric, expected order)
mu_T(state variable, time/path constraint, shape predicate)
mu_F(model hierarchy, fidelity metric, dominance relation)
```

这种设计使算子具备受约束的通用性：

1. 通用性来自守恒、单调、收敛、轨迹、偏序这些跨科学计算领域共享的数学结构；
2. 具体实现依赖领域模型、物理量、数值方法和有效输入域。

建议写入论文的克制表述：

> The proposed operators are not universal at the syntactic level; they are generalizable at the semantic-class level and instantiated through domain-specific physical, numerical, or mathematical constraints.

中文表述：

> 这些算子不是语法层面的通用，而是语义类别层面的可泛化。其通用性来自守恒、单调、收敛、轨迹、偏序这些跨科学计算领域共享的数学结构；其具体实现则必须依赖领域模型实例化。

## 4. 反例：物理常数扰动算子

一个重要反例是 **物理常数扰动算子**。

若将算子直接定义为：

> 改变物理常数的数值，例如把重力加速度 `g = 9.81` 改为 `g = 10.0`，或把中子衰变常数、截面参数、热导率扰动一定比例。

这个算子看似是领域语义层面的，但不具备跨领域通用性。

在核工程中，扰动截面、衰变常数、反应性参数可能是合理 mutant，因为它模拟核数据错误、单位错误或数据库读取错误。

在 CFD 中，扰动黏度、密度、热导率也可能合理，因为它模拟材料属性错误。

但在以下软件中，未必存在明确的物理常数：

1. 通用 ODE 求解器；
2. 数值积分库；
3. 线性代数库；
4. 优化算法库；
5. FFT 或插值算法库。

如果强行套用物理常数扰动，这个算子就无法实例化，或者只能退化为无意义的参数扰动。

因此：

> 物理常数扰动不是合格的抽象 Domain-Semantic Mutation Operator。它只是某些物理仿真领域的实例级算子。

更好的抽象方式应是：

```text
model-parameter perturbation under semantic constraint
```

或更具体：

```text
conservation-breaking parameter perturbation
```

这样才可能泛化：

1. 核工程：扰动截面或衰变常数，破坏中子平衡；
2. CFD：扰动物性参数，破坏质量、动量或能量守恒；
3. ODE benchmark：扰动方程参数，破坏已知解析关系；
4. 优化算法：扰动目标函数参数，破坏单调性或凸性预期。

该反例说明一条原则：

> 不能把某领域对象直接提升为通用算子。只有当它能抽象为跨领域共享的语义失效类别时，才具备理论价值。

## 5. 泛化性如何检验

P2 必须设计 cross-domain evaluation，否则无法证明 Domain-Semantic Mutation Operators 具备理论价值。

建议至少包含三类案例：

1. 核工程案例：例如 NUIT、OpenMC、SACOS 或 PKE；
2. 通用数值计算案例：ODE/PDE solver、数值积分、优化算法；
3. 工程仿真或多物理案例：CFD、热传导、耦合仿真，资源不足时可用公开简化模型。

建议指标：

| 指标 | 含义 |
|---|---|
| Instantiation coverage | 五类抽象算子中有多少能在各领域实例化 |
| Fault detection transferability | 同一抽象算子在不同领域是否都能产生可被 MR 检出的有效 mutants |
| Non-equivalent mutant rate | 生成的 mutants 中有多少不是等价或无意义 |
| Pattern-aligned kill rate | 对应元模式的 MR 是否更容易杀死对应语义算子生成的 mutants |
| Cross-domain consistency | 不同领域中算子有效性的排序是否稳定 |

建议设置可证伪条件：

1. 若某抽象算子只能在单一子领域实例化，则不能声称跨 SCP 泛化；
2. 若某算子生成大量等价 mutants，则该算子不具备有效性；
3. 若对应元模式的 MR 无法显著杀死对应语义算子生成的 mutants，则 P1-P5 与算子类别之间的映射应被修正；
4. 若不同领域中的算子有效性完全不一致，则只能主张领域内有效，不能主张语义类别层面的泛化。

## 6. 当前理论空缺

Domain-Semantic Mutation Operators 目前至少存在以下理论空缺。P2 的任务就是把它们从合理直觉推进为可实例化、可证伪、可度量、可比较的形式体系。

### 6.1 抽象层级还不够精确

需要明确三层：

```text
semantic class -> domain instantiation -> code-level injection
```

例如：

```text
Conservation-breaking -> 中子守恒破坏 -> 修改 delayed neutron source term
```

理论必须说明哪一层具备通用性，哪一层依赖领域。否则无法回答"通用性到底在哪里"。

### 6.2 算子与元模式之间不是一一对应

直觉上 P1 对应 conservation-breaking，P2 对应 monotonicity-breaking，但实际可能是多对多关系。

例如：

1. 边界条件错误可能同时破坏 P1 守恒性、P2 单调性和 P4 轨迹性；
2. P3 收敛 MR 可能检出浮点误差、迭代停止错误、网格设置错误。

理论需要定义 `operator class mu_j` 与 `meta-pattern P_i` 之间的 one-to-many 或 many-to-one 关系，而不是硬绑定。

### 6.3 等价 mutant 问题没有解决

语义变异不等于有效变异。某些 domain-semantic mutant 可能：

1. 不改变可观测输出；
2. 只在未测试区域表现异常；
3. 被数值容差掩盖；
4. 仍满足所有已知 MR。

理论必须定义：

```text
observable mutant
MR-reachable mutant
equivalent semantic mutant
```

否则 MMS 会被等价 mutant 污染。

### 6.4 语义变异的有效性缺少判定标准

传统 mutation testing 有"模拟真实程序员错误"的经验假设。语义变异需要新的有效性标准。

候选标准：

1. 是否对应真实科学计算故障；
2. 是否可由领域专家解释；
3. 是否破坏明确物理、数学或数值约束；
4. 是否能在不导致程序崩溃的情况下产生可观测行为；
5. 是否覆盖某类 FMECA/PIRT 风险。

没有这些标准，审稿人可能质疑 operators 是人为设计的。

### 6.5 泛化性缺少可证伪条件

需要说明什么时候算子不泛化。

例如：

1. 一个抽象算子若在多个 SCP 子领域中只能在一个子领域实例化，就不能声称跨 SCP 通用；
2. 一个算子如果生成大量等价 mutants，也不能算有效；
3. 一个算子如果不能被任何合理 MR 检出，则它对 MR adequacy 的评估价值有限。

### 6.6 与传统语法 mutation 的关系需要澄清

不能简单说语法 mutation 低级或无用。

更严谨的表述是：

1. 语法 mutation 评估代码级测试套件 adequacy；
2. 领域语义 mutation 评估 MR 集合对科学计算行为约束的 adequacy；
3. 两者目标不同，可能互补。

### 6.7 成本模型缺失

科学计算 mutant 运行代价高。理论如果没有成本维度，会不完整。

需要定义：

```text
cost(mu_j)
kill gain per cost
cost-normalized MMS
```

否则"充分性"可能不可执行。

### 6.8 与统一 MT 理论的接口还需形式化

当前讨论需要最终落到统一理论符号系统：

```text
Pi = {P1, ..., P5}          元模式集合
F = {phi_1, ..., phi_K}     故障模型
Mu = {mu_1, ..., mu_K}      语义变异算子集合
Detect(m, mu(P))            MR 对 mutant 的检出谓词
MMS(M, Mu, S)               MR 集合在程序集 S 上的变异充分性
```

理论接口：

1. `Pi` 组织 MR 的形态；
2. `F / Mu` 组织 MR 的目标；
3. `MMS` 连接 MR 集合与故障模型；
4. P2 通过实验验证 `Pi -> Mu -> MMS` 的可实例化性。

## 7. 研究假设

P2 的研究假设应服务一个核心论断：

> MR adequacy 不能只看 pattern coverage，必须看 MR 对领域语义故障的检出能力。

建议设置五个主假设，分别覆盖算子有效性、语义相关性、元模式对齐、跨领域泛化性和 MMS 解释力。

### H1. 领域语义变异算子有效性假设

> Domain-semantic mutation operators can generate non-equivalent and MR-reachable mutants in scientific computing software.

含义：

领域语义变异算子不是空泛概念，而是能够生成可执行、非等价、且可被 MR 测试触达的 mutants。

建议指标：

1. executable mutant rate；
2. non-equivalent mutant rate；
3. MR-reachable mutant rate；
4. invalid mutant rate。

可证伪条件：

1. 大量 mutants 无法执行；
2. 多数 mutants 与原程序等价；
3. 多数 mutants 只改变不可观测行为；
4. 多数 mutants 无法被任何 MR 触达。

理论位置：

H1 是 P2 的基础假设。若 H1 不成立，后续 MMS、元模式对齐和跨领域泛化均失去基础。

### H2. 语义变异相关性假设

> Domain-semantic mutants are more effective than language-syntactic mutants for evaluating metamorphic relation adequacy in scientific computing software.

含义：

本文不否定传统语法变异。H2 的主张是：在科学计算软件中，若目标是评估 MR 集合的 adequacy，领域语义 mutants 比语言语法 mutants 更相关、更可解释。

比较对象：

1. domain-semantic mutants；
2. language-syntactic mutants。

建议指标：

1. MR kill rate；
2. non-equivalent mutant rate；
3. fault interpretability；
4. pattern alignment；
5. cost-normalized kill rate。

可证伪条件：

1. 语法 mutants 与语义 mutants 的 MR 检出结构无显著差异；
2. 语义 mutants 的等价率更高；
3. 语义 mutants 不能提供更清晰的故障解释；
4. 语义 mutants 的成本显著更高且检出收益不足。

理论位置：

H2 用于区分本文与传统 mutation testing。它说明 P2 的目标不是替代语法变异,而是为 MR adequacy 提供更匹配科学计算语义的评估对象。

### H3. 元模式-语义故障对齐假设

> MRs are more effective at detecting mutants whose semantic fault class aligns with their meta-pattern than mutants from non-aligned classes.

含义：

P1-P5 元模式不只是分类标签。若元模式具备理论价值，则对应元模式的 MR 应更容易检出语义类别对齐的 mutants。

示例：

1. P1 守恒 MR 更容易检出 conservation-breaking mutants；
2. P2 单调 MR 更容易检出 monotonicity-breaking mutants；
3. P3 收敛 MR 更容易检出 convergence-breaking mutants；
4. P4 轨迹 MR 更容易检出 trajectory-distorting mutants；
5. P5 偏序 MR 更容易检出 fidelity-order-breaking mutants。

建议指标：

1. aligned kill rate；
2. non-aligned kill rate；
3. aligned / non-aligned odds ratio；
4. MR x mutant kill matrix structure；
5. pattern-level MMS。

可证伪条件：

1. aligned kill rate 不高于 non-aligned kill rate；
2. kill matrix 无明显结构；
3. 某些元模式长期无法检出对应语义故障；
4. 多数 MR 的检出能力与其元模式归属无关。

理论位置：

H3 是 P2 最关键的理论假设。它直接验证统一理论中的接口：

```text
Pi(meta-patterns) -> F / Mu(domain-semantic fault classes) -> Detect
```

若 H3 成立，P1 的元模式矩阵就不只是形态分类，而是能连接故障模型和充分性度量。

### H4. 跨领域可实例化假设

> The abstract domain-semantic mutation classes can be instantiated across multiple scientific computing subdomains while preserving their semantic intent.

含义：

Domain-Semantic Mutation Operators 具备受约束的通用性。其通用性不在代码语法层，而在语义类别层；具体实现必须通过领域模型实例化。

建议覆盖的 SCP 子领域：

1. 核工程软件；
2. 通用数值算法或 ODE/PDE 求解程序；
3. 工程仿真或多物理简化模型。

建议指标：

1. instantiation coverage；
2. valid mutant rate by domain；
3. non-equivalent mutant rate by domain；
4. domain-specific adaptation effort；
5. cross-domain consistency of operator effectiveness。

可证伪条件：

1. 某个抽象算子只能在单一子领域实例化；
2. 不同领域实例化后语义含义发生漂移；
3. 不同领域的 valid mutant rate 差异过大；
4. 某些领域无法形成任何有意义的 semantic mutants。

理论位置：

H4 检验 P2 是否具备理论泛化价值。若 H4 不成立，P2 只能作为单案例方法论文，不能支撑统一 MT 理论。

### H5. MMS 充分性解释假设

> MR Mutation Score explains MR set adequacy better than pattern coverage alone.

含义：

P1 的 pattern coverage 不等于 P2 的 testing adequacy。MMS 应当提供额外解释力，用于识别关键 MR、冗余 MR 和最小充分 MR 子集。

比较对象：

1. pattern coverage only；
2. MMS only；
3. pattern coverage + MMS；
4. cost-normalized MMS。

建议指标：

1. mutant detection explained variance；
2. redundancy identification accuracy；
3. minimal MR subset quality；
4. correlation with expert adequacy judgement；
5. cost-normalized adequacy gain。

可证伪条件：

1. pattern coverage 已能解释绝大多数检出能力；
2. MMS 无法区分冗余 MR 与关键 MR；
3. MMS 与专家判断或实际故障检出无相关；
4. cost-normalized MMS 无法改善 MR 集合选择。

理论位置：

H5 验证统一理论为什么需要充分性度量。若 H5 成立，则说明 P1 的元模式覆盖必须与 P2 的 mutation-based adequacy 结合，才能支撑 P4 的 MT 完备性论证。

### 假设优先级

若实验资源有限，必须优先保住：

1. H3 元模式-语义故障对齐假设；
2. H5 MMS 充分性解释假设。

原因：

1. H3 证明 `Pi` 不是单纯分类，而能连接故障模型；
2. H5 证明统一理论不能只依赖元模式覆盖，还需要 MMS；
3. H1 是前置有效性检查，必须报告；
4. H2 和 H4 是增强假设，可根据资源规模做强或做弱。

## 8. 对 P2 论文骨架的影响

P2 不应以普通 mutation testing 论文的方式写。

推荐主线：

```text
P1-P5 meta-patterns
-> domain-semantic fault classes
-> domain instantiation rules
-> executable mutants
-> MR detection matrix
-> MMS and adequacy analysis
```

推荐题目：

> Domain-Semantic Mutation Operators for Measuring Metamorphic Testing Adequacy in Scientific Computing Software

比原题 *Metamorphic Mutation Operators and Adequacy Measurement for Scientific Computing Software* 更准确,因为它明确区分本文与传统语法 mutation testing。

P2 的关键论断：

> MR adequacy should be measured not only by pattern coverage, but also by mutation-based fault detection capability under domain-semantic fault models.

中文表述：

> MR 充分性不应只由元模式覆盖率衡量，还必须由其在领域语义故障模型下的检出能力来衡量。
