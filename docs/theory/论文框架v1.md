# How Complete Are Metamorphic Relation Patterns? An Empirical Audit in Scientific Computing Software

## 0. 论文定位

本文定位为面向 Information and Software Technology 的经验审计论文，而不是纯理论论文、普通综述论文或工具论文。

核心问题是：已有蜕变关系元模式是否足以解释科学计算软件中已经报道和使用的 MR？如果不能，边界在哪里？

本文不主张证明绝对完备性。本文将完备性操作化为一种可审计、可复查、可反驳的经验问题：给定一个科学计算软件 MR 语料库，现有元模式体系能覆盖多少 MR，哪些 MR 只能模糊归类，哪些 MR 构成孤儿 MR，并且这些结果对未来 MT adequacy 与统一理论有什么含义。

一句话贡献：

> 本文首次将 MR pattern completeness 从概念主张转化为可审计的经验研究问题，并在科学计算软件语料上评估五类 MR 元模式的覆盖力、边界与理论含义。

## 3. 核心贡献

### C1. MR Pattern Completeness Audit Framework

提出一个 MR 元模式完备性审计框架。

该框架回答三个问题：

1. 给定一个 MR 语料库，现有元模式体系 P1-P5 能解释多少 MR？
2. 哪些 MR 可以归类但存在边界模糊或标注分歧？
3. 哪些 MR 无法归入现有元模式，并对理论扩展构成压力？

该贡献的关键不是提出新分类，而是提出一种可复查的审计方法，使 pattern completeness 可以被经验检验。

### C2. A Curated SCP-MR Corpus

构建一个面向科学计算软件的 MR 语料库。

建议覆盖以下 SCP 子类：

1. 数值算法与数学库
2. ODE/PDE 求解程序
3. 蒙特卡洛与随机仿真程序
4. 核工程软件
5. 多物理耦合与工程仿真程序

每条 MR 至少标注以下字段：

| 字段 | 含义 |
|---|---|
| MR ID | 唯一编号 |
| Source | 来源文献或软件制品 |
| Software / domain | 软件或应用领域 |
| SCP subdomain | 科学计算子类 |
| Input transformation | 输入变换 |
| Output relation | 输出关系 |
| Mathematical / physical rationale | 数学或物理依据 |
| Meta-pattern | P1-P5 或 orphan |
| Confidence | 稳定、模糊、孤儿 |
| Fault tendency | 可能检出的故障类型 |
| Nuclear relevance | 是否属于核工程子集 |

该语料库是未来 MT 统一理论中支柱 II 的经验基础。

### C3. Empirical Coverage and Orphan MR Analysis

对 P1-P5 元模式进行覆盖率审计。

结果分为三类：

| 类型 | 定义 | 理论含义 |
|---|---|---|
| Covered MR | 可稳定归入 P1-P5，标注一致性高 | 支持元模式核心骨架 |
| Ambiguous MR | 可归入 P1-P5，但依赖解释或标注一致性低 | 暴露定义边界，需要细化判定规则 |
| Orphan MR | 无法合理归入 P1-P5 | 构成可证伪证据，提示潜在 P6/P7 或新维度 |

该贡献是全文的关键。论文不应只报告高覆盖率，而应重点分析孤儿 MR 和模糊 MR，因为它们决定未来统一理论的边界声明是否可信。

### C4. Implications for MT Adequacy Theory

将审计结果映射到 MT adequacy 与未来统一理论。

重点回答：

1. P1-P5 是否足以作为 SCP 的元模式核心骨架？
2. 哪些元模式最稳定，哪些元模式定义最脆弱？
3. 哪些 SCP 子类暴露出系统性空缺？
4. 孤儿 MR 是否提示新增元模式、拆分已有元模式，或引入非元模式维度？
5. 这些结果如何支撑 MT 完备性从“绝对穷尽”转向“可审计边界声明”？

该贡献为后续 P2、P4、P5 建立接口。

## 5. 元模式 Codebook

本文使用 P1-P5 作为审计用元模式，不在本文中声称其演绎完备。

| 编号 | 名称 | 核心判定问题 | 典型形式 |
|---|---|---|---|
| P1 | Conservation | 输入变换后是否存在不变量、守恒量或对称不变性？ | invariant, symmetry, conservation law |
| P2 | Monotonicity | 输入参数按某方向变化时，输出是否保持单调方向？ | order-preserving relation |
| P3 | Convergence | 网格、步长、样本量、迭代次数变化时，输出是否趋于稳定或参考极限？ | limit or refinement relation |
| P4 | Trajectory | 输出序列、路径、时间演化或状态转移是否满足形态约束？ | temporal or path constraint |
| P5 | Partial Order / Fidelity | 不同模型、算法、精度层级之间是否存在保真度或近似偏序？ | fidelity hierarchy, approximation order |

每个元模式在正文中都应包含：

1. 操作化定义
2. 包含标准
3. 排除标准
4. 典型 MR 示例
5. 非例子
6. 常见混淆模式

3. External validity：SCP 语料是否能代表全部科学计算软件
4. Conclusion validity：覆盖率统计是否过度解释
5. Publication bias：已发表 MR 是否偏向容易描述的关系

## 10. 预期摘要草稿

Metamorphic testing alleviates the test oracle problem by checking necessary relations among multiple executions of a program. However, the adequacy of a set of metamorphic relations remains difficult to assess: while many relation patterns and taxonomies have been proposed, little empirical evidence exists on how completely they cover the relations used in scientific computing software. This paper presents an empirical audit of metamorphic relation pattern completeness in scientific computing software. We construct a curated corpus of MRs from scientific computing domains, operationalize five meta-patterns as an audit codebook, and classify each relation as covered, ambiguous, or orphan with respect to the current taxonomy. Our study quantifies the coverage of the five meta-patterns, characterizes their distribution across scientific computing subdomains, and analyzes orphan relations that expose the boundary of the taxonomy. The results provide an empirical basis for treating metamorphic testing completeness as an auditable boundary statement rather than an exhaustive guarantee, and offer implications for future MT adequacy metrics and verification practice in scientific computing software.
