## Ranked findings

### R1 — CRITICAL (desk-reject): the packaged `main.tex` does not compile; it has two preambles and exposes the IST/elsarticle frontmatter

`submission/TOSEM_fastimpact_20260707/main.tex` contains:
- `\documentclass[manuscript,screen,review]{acmart}` at **L3** AND
  `\documentclass[review,12pt,authoryear]{elsarticle}` at **L110**;
- `\begin{document}` at **L98** AND again at **L189**;
- an embedded `\begin{frontmatter}` at **L191** (elsarticle-only) plus the leaked comment
  fragment `by venues/<venue>/build.py (TOSEM: acmart 2.19).` at **L106**;
- corrupted preamble from destructive text substitution: `\providecommand{}{...}` (**L185**,
  empty first argument — a LaTeX error) and `\newunicodechar{$\forall$}{\ensuremath{\forall}}`
  (**L155**; `\newunicodechar` requires a single character, not `$\forall$`).

Root cause: this file was generated by an **older build.py** that split the source on the
**first** `\end{frontmatter}` — which is the one inside the header comment of
`source/main.tex` **L7** (`% ... generated from the body after \end{frontmatter} ...`) — thereby
dragging the entire elsarticle preamble into the "body". The **current** `venues/tosem/build.py`
already fixes this (`return tex.rsplit(marker, 1)[1]`, **L133**, with the explanatory comment at
**L130–132**). So the package is simply **stale and was never regenerated after the fix**.

Contrast (both sides): broken output `submission/TOSEM_fastimpact_20260707/main.tex:3,110,189,191`
vs the correct splitter `venues/tosem/build.py:133`. The clean supplementary in the same package
(`.../supplementary.tex:3` — single `\documentclass`, single `\begin{document}`) proves the bug is
specific to the stale main build.

Extra embarrassment: because the elsarticle frontmatter is dragged in, the "TOSEM" file exposes
the `\begin{highlights}` block and IST-style `\begin{keyword}...\sep...` frontmatter
(`source/main.tex:124–146`) that the acmart build is supposed to strip — i.e. a TOSEM reviewer
would see an Elsevier/IST skeleton inside an ACM submission.

**Fix:** rebuild with the current `build.py --force` and re-verify (`grep -c '\documentclass'`
must return 1). Do not hand-patch the stale file.

### R3 — MEDIUM (editorial policy: front-load negatives): the Introduction *prose* leads with the industrial positive and relegates the H1–H4 misses to a single table cell

The abstract correctly front-loads the failures (`source/main.tex:138`: "The pre-registered
instantiability, effect-size, cross-class-consistency, and attribution thresholds are not met…").
But the Introduction prose does **not** state the threshold misses anywhere; instead
`source/main.tex:178–188` foregrounds the industrial arm as a positive
("strengthens the semantic-mutant argument"). The only early appearance of the negatives is a
cell of Table 1 (`source/main.tex:271–273`, claim-evidence-map row 4: "H1–H4 failures …").
Under the stated editorial policy (negatives front-loaded in abstract **and** intro **and** early
results), the intro narrative buries the four headline negatives in a table while the one positive
gets a paragraph of prose.

**Fix:** add one sentence to §Motivation-and-Scope (near `source/main.tex:196–198`) stating
plainly that all four pre-registered thresholds were missed and that the paper treats those misses
as the diagnostic result, before the industrial-arm paragraph.

### R4 — MEDIUM-LOW (policy, venue-neutral source only): the Highlights omit every negative result

`source/main.tex:124–132` lists seven Highlights, all positive/neutral (generalizes MS, effect
fibers, 5.14% overlap, HP/SI/TF unreachable, industrial separation, boundary map, adjoint arm).
None mentions that H1–H4 were not met. This is pure burying of the negatives in the one place a
skim-reader looks. Low TOSEM risk because the acmart build (`venues/tosem/build.py`) drops

**Fix:** replace one Highlight with a "pre-registered thresholds not met; failures delimit
applicability/MR-design/attribution" bullet, or accept knowingly that this is dead for TOSEM.

### R7 — LOW (wording gradient on a marginal result): cover-letter "confirm" is the strongest verb in the chain

`venues/tosem/cover_letter.md:18` "used to **confirm** the paper's construct separation" vs the
abstract's "**supporting** the paper's construct separation" (`source/main.tex:138`) and the body's
"**strengthens** the paper's main argument" (`source/main.tex:2491`). The underlying number is a
marginal four-group result (mean diff +0.101, Holm-adjusted **p=0.046**, δ=+0.247, explicitly
"marginal … reported with its fragility", `source/main.tex:2446–2448`). The construct *separation*
itself (non-nesting) is robustly shown by the same-case contrast (27/34, 26/34, 19/34,
`source/main.tex:2460–2463`) and the four named counterexamples (`source/main.tex:2478–2487`), so
"confirm" is defensible — but it is the least-hedged word and rests rhetorically on a p just under
0.05. The inference-permissions row licenses only "inferential within the 34-case pool; no
corpus-level claim" (`source/main.tex:1925–1927`).

**Fix:** harmonize the cover letter to "support"; keep "confirm" only for the non-nesting
separation, not the marginal dominance.
