# Release Checklist — P2 SMS audit

> This checklist drives three things in lockstep: (i) IST submission,
> (ii) Zenodo archival, (iii) GitHub public release. Each numbered
> step lists the verification command and the artefact it produces.
> Tick items off as you go.

---

## A. Repository hygiene (final pass before tagging)

- [ ] `git status` clean (no uncommitted file outside this checklist's
      planned commit).
- [ ] `pytest -q` reports **192 passed** (or current count from
      `docs/release_2026-05-03/sanity_check.log`):
      ```
      PYTHONPATH=src python3 -m pytest tests/ -q
      ```
- [ ] No secrets in tracked files:
      ```
      git ls-files | xargs grep -lE "sk-[a-zA-Z0-9]{20,}" 2>/dev/null
      ```
      (expected: only `.env.example` with placeholders)
- [ ] `.env` confirmed gitignored: `git check-ignore .env` returns
      `.env`.
- [ ] LaTeX byproducts (`*.aux`, `*.log`, `*.out`, `*.spl`) absent
      from `submission/` and `archive/submission_drafts/`.
- [ ] SSOT JSON regenerates without diff:
      ```
      PYTHONPATH=src SMS_VERSION=v4 P2_PRIMARY_VERSION=v3b \
        python3 scripts/build_paper_numbers.py
      git diff --stat data/results/paper_numbers_v4.json
      ```
      (expected: empty)

## B. Zenodo upload

- [ ] Update `replication/.zenodo.json`:
      - [ ] `creators[].orcid` filled in (or marked `<TBD>` if absent)
      - [ ] `creators[].affiliation` filled in
      - [ ] `description` reflects round-9 content
      - [ ] `keywords` final
      - [ ] `version` set to `1.0.0`
- [ ] Update `replication/CITATION.cff`: same author / version.
- [ ] Rebuild bundle:
      ```
      cd replication && bash build_zip.sh
      ```
      Produces `replication.zip`. Confirm size and SHA against
      `MANIFEST.txt` (regenerated by the script).
- [ ] Tag the commit:
      ```
      git tag -a v1.0.0-zenodo -m "Zenodo archive snapshot"
      ```
- [ ] Upload `replication.zip` via the Zenodo web UI under sandbox
      first (`https://sandbox.zenodo.org/`), confirm metadata renders.
- [ ] Promote to production Zenodo (`https://zenodo.org/`); copy the
      minted DOI.
- [ ] Substitute the DOI placeholder in:
      - [ ] `README.md`
      - [ ] `ZENODO.md`
      - [ ] `DATASET.md` §9
      - [ ] `论文初稿P2_IST.md` §8 (Data and code availability)
      - [ ] `submission/p2_ist_final.tex` (regenerate via
            `scripts/build_ist_submission_v9.sh`)
- [ ] Commit DOI substitution; update `CHANGELOG.md` `[Unreleased]`
      → `[v1.0.0]` with the Zenodo DOI.

## C. GitHub repository

- [ ] Create empty public repo on GitHub (suggested name:
      `p2-sms-audit`). Do not initialise with a README.
- [ ] Confirm local remote:
      ```
      git remote add origin git@github.com:<owner>/p2-sms-audit.git
      git remote -v
      ```
- [ ] First push:
      ```
      git push -u origin main
      git push --tags
      ```
- [ ] Verify on GitHub:
      - [ ] `README.md` renders (table of contents, citation block)
      - [ ] `LICENSE` recognised (MIT badge appears)
      - [ ] `.github/workflows/sanity.yml` triggers on push;
            `Actions` tab shows green run
      - [ ] `archive/` browsable; large PDFs (~1 MB each) load
- [ ] Create a GitHub Release:
      - Tag: `v1.0.0-submission`
      - Title: "P2 SMS audit — submission round 9"
      - Body: paste `CHANGELOG.md` `[round-9]` section
      - Attach: `submission/p2_ist_final.pdf`,
        `submission/cover_letter_final.pdf`,
        `replication/replication.zip` (if < 100 MB)
- [ ] Add Zenodo DOI badge to `README.md` once DOI is minted:
      ```
      [![DOI](https://zenodo.org/badge/DOI/10.5281/zenodo.<NNN>.svg)](https://doi.org/10.5281/zenodo.<NNN>)
      ```

## D. IST EVISE submission

- [ ] Author profile up to date in EVISE (ORCID, affiliation,
      conflicts of interest).
- [ ] Cover letter proofread once more (`submission/cover_letter_final.pdf`).
- [ ] Manuscript files uploaded:
      - [ ] `submission/p2_ist_final.pdf` (compiled article)
      - [ ] `submission/p2_ist_final.tex` (LaTeX source)
      - [ ] `submission/p2_ist_final.docx` (Word backup, IST asks
            for either tex or docx)
      - [ ] `figs/fig{1,2,3}*.png` as separate figure files
- [ ] Highlights, Abstract, Keywords, suggested reviewers, declared
      conflicts of interest — fill in EVISE form.
- [ ] Data and Code Availability statement: paste the Zenodo DOI URL.
- [ ] NOETHER terminology gate passes:
      - [ ] Run the fixed **Gate A** command in
            `docs/decisions/2026-07-08-noether-mp-terminology-precheck.md`
            (single-quoted pattern, includes the LaTeX-form alternatives
            `mathrm\{mut\}_[CMGTF]` and `mut\\_[CMGTF]`, scans both
            `main.tex` and `supplementary.tex`); expected: no hits
      - [ ] No reader-facing use of `CE/OS/HP/TF/SI` as concept names
      - [ ] MR MetaPattern / MR Family terminology follows
            `docs/naming_convention.md`
- [ ] Submit.
- [ ] Save the EVISE confirmation email; record the submission ID
      in `docs/STATE.md` under "Stage".

## E. Post-submission watchpoints (first 30 days)

- [ ] Watch GitHub Issues; respond within 5 business days; mark
      replication failures as `priority/high`.
- [ ] If any errata surface (paper number / table mismatch), open an
      `errata-track` issue, fix, and tag a `v1.0.1-errata` release;
      do **not** silently overwrite the Zenodo archive — mint a new
      version on Zenodo.
- [ ] Track citations / Altmetric (manually for now).
