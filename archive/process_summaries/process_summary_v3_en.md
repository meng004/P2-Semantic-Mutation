## 4. Key lessons

1. **Data-driven framing changes must be explicitly disclosed.** Plans are written before data; when data returns and changes the optimal framing, write the change into the letter and the process record — do not pretend the plan said this all along.
2. **Subagent batch grouping**: bundle "independent Edit + one commit / Task" mechanical work into one agent; keep work that needs external information (git log, data computation) in the main session. This round's 7-tasks / 1-agent / 7-commits run validated this pattern.
3. **The humanizer's em-dash zero-tolerance rule is most expensive in the letter** — letters are written from scratch and tend to have many em-dashes. Next time, write the letter with colons / parens / periods from the start to avoid bulk replacement.
4. **`postprocess_unicode.py` hardcoded path** is a small toolchain debt in the v2 → v3 build chain; the next round (or any free time) should refactor it to accept a parameter.
5. **All-inline text-edit revisions** under-ran the subagent-overhead budget — pure-text revisions of similar size could go all-inline next time.
