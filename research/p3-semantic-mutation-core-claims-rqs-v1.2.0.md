# P3 v1.2.0 核心主张、研究问题与贡献边界

> **状态：** 权威论文范围基线（2026-07-12）  
> **适用对象：** P3-SemanticMutation 的论文提纲、实验解释、结果写作与 P12 证据消费  
> **取代范围：** 取代既有“MR 集合充分性 / held-out portfolio decision value 为论文核心”的叙事优先级，但不删除相关协议、实验控制和历史设计材料  
> **证据纪律：** 本文档冻结的是论文身份、RQ、预期主张及措辞边界，不把尚未完成的实验写成已观察结果

## 1. 论文身份

P3 是一篇**面向蜕变测试（MT）的语义变异系统论文**。其核心不是比较两种 MR 识别提示，也不是证明某个 MR 目录选择策略优于另一个策略，而是建立并验证一套由以下三个部分构成的系统：

1. **语义变异算子与可控语义变异体生成；**
2. **等价变异体的显式判定、保留与不确定性处理；**
3. **用于评价 MT 完备性的语义变异得分。**

系统的主要外部有效性检验是：基于可控语义变异体得到的评价，是否与同一 MT 方法在开发者真实语义缺陷上的检测表现一致。

### 1.1 中心研究问题

> 如何构建一套可生成、可判定、可计分，并能反映真实缺陷检测能力的语义变异系统？

### 1.2 中心论证链

```text
语义变异算子
→ 可控语义变异体
→ 等价变异体处理
→ 语义变异得分
→ 对 MT 方法完备性的度量
→ 与真实缺陷检测结果的一致性验证
```

### 1.3 一句话主张

> P3 提供的不是更多代码修改，而是一种以语义缺陷机制为单位、显式处理等价性与执行不确定性、并通过真实开发者缺陷校准的 MT 完备性度量系统。

## 2. 核心构件

### 2.1 语义变异算子

语义变异算子描述一种抽象的语义缺陷机制，并规定：

- 适用前提；
- 语义角色和目标代码位置；
- 受控代码变换；
- 可调参数；
- 预期语义效应；
- trigger 与可观察性义务；
- 已知等价风险；
- 生成器版本与内容哈希；
- 支撑该算子的跨项目证据。

“语义”修饰的是缺陷目标、机制和认证义务，不表示代码编辑脱离语法。每个变异体仍由有限、可审计的程序修改生成。

### 2.2 可控语义变异体

一个候选体只有在以下条件下，才能进入确认性语义变异体集合：

1. 原程序在冻结语义契约下通过；
2. 候选体由冻结生成器在冻结站点生成；
3. 修改非空、唯一、可解析、可构建且不包含额外修改；
4. 原程序和变异程序使用同一来源锁、依赖锁和执行环境；
5. 冻结 trigger 被实际覆盖；
6. 在冻结抽象、输入域和容差下观察到稳定语义分歧；
7. 变异体未被机器可核验证书判定为等价；
8. 原始输出、日志、环境与判读均可内容寻址。

语义变异体的有效性不得由正在被评价的 MR 是否杀死它来决定。

### 2.3 等价变异体处理

等价只相对于冻结元组定义：

\[
(\alpha,\mathcal{X},E,\tau),
\]

其中 \(\alpha\) 是语义输出抽象，\(\mathcal{X}\) 是承诺输入域，\(E\) 是来源、依赖与运行环境，\(\tau\) 是数值、异常、终止与超时语义。

有限样本上的输出相等、测试存活、MR 零 kill、构建失败或 trigger 未覆盖，均不能独立证明等价。`CERTIFIED_EQUIVALENT` 只允许来自机器可核验的证书，例如：

- 规范化 AST 或可执行文件同一性；
- 对冻结有限域的穷举；
- 可复核的 SMT / 符号等价证明；
- 可复核的不可达或覆盖前写证明；
- 在明确前提下可复核的代数恒等证明。

每个候选体必须进入一个互斥的最新状态：

| 状态 | 解释 | 主要得分处理 |
|---|---|---|
| `INVALID_MUTANT` | 生成、解析、构建或修改完整性失败 | 排除并报告生成失败 |
| `DUPLICATE_MUTANT` | 与另一候选体重复 | 去重，保留来源链接 |
| `CERTIFIED_EQUIVALENT` | 具有机器可核验证书 | 排除并公开证书 |
| `CONFIRMED_NON_EQUIVALENT` | 存在稳定语义分歧见证 | 纳入主要分母 |
| `EQUIVALENCE_UNRESOLVED` | 证据不足以证明等价或非等价 | 进入保守界或单独报告 |
| `TRIGGER_UNEXERCISED` | 未进入算子适用域 | 不解释为等价或科学阴性 |
| `INFRASTRUCTURE_UNRESOLVED` | 来源、构建或环境失败 | 单列基础设施损耗 |

### 2.4 语义变异得分

P3 不把传统 mutation score 简单换一个 mutant 集合，而是显式报告算子家族、等价性和执行状态。

令 \(M_{\mathrm{neq}}\) 为确认非等价、可执行且 trigger 覆盖的冻结语义变异体集合，\(K_R(m)\) 表示 MR 集合 \(R\) 是否杀死变异体 \(m\)。实例级严格得分为：

\[
\mathrm{SMS}_{\mathrm{strict}}(R)
=
\frac{\sum_{m\in M_{\mathrm{neq}}}K_R(m)}{|M_{\mathrm{neq}}|}.
\]

P3 至少同时报告：

1. **`SMS_strict`：** 以确认非等价、可执行、trigger 覆盖的变异体为分母；
2. **`SMS_conservative`：** 将满足其余准入条件但等价性未决的候选体纳入保守分母；
3. **family-balanced SMS：** 先在算子家族内计分，再对家族等权平均；
4. **instance-weighted SMS：** 传统实例级聚合，作为伴随结果；
5. **equivalence burden：** 等价、等价性未决及相关证据成本；
6. **execution funnel：** 无效、构建失败、trigger 未覆盖和基础设施未决的完整漏斗。

family-balanced SMS 应作为主要完备性度量候选，因为它避免候选体较多的算子家族支配总分。最终 primary / sensitivity 角色必须在读取确认性 kill matrix 前冻结。

## 3. 研究问题

### RQ1：语义变异算子及可控生成

> **RQ1：归纳得到的语义变异算子能否跨项目生成有效、可执行、可触发且具有预期语义分歧的可控语义变异体？**

核心分析包括：

- 可迁移算子家族和变体数量；
- 生成、解析、构建和 trigger 覆盖率；
- 语义分歧确认率与重复稳定性；
- 开发项目与验证项目之间的源不相交复现；
- 项目、算子家族、变体及失败类型分布；
- 目标项目中的适用性、不可适用性与迁移边界。

RQ1 不以候选算子或静态站点绑定数量作为成功结论。只有真实双臂构建和冻结见证执行后，才能确认算子或变体。

### RQ2：等价处理与语义变异得分

> **RQ2：如何识别和处理等价、等价性未决、未触发及基础设施失败的变异体，并据此构造稳健、可解释的语义变异得分？**

核心分析包括：

- 证书型等价变异体比例及证书类型；
- 等价性未决比例与对得分区间的影响；
- `SMS_strict`、`SMS_conservative`、family-balanced 与 instance-weighted 结果；
- trigger、容差、重复策略和环境锁的敏感性；
- 无效候选、基础设施失败和科学阴性的分离；
- 得分是否能稳定区分完备性不同的 MT 方法。

RQ2 的创新点不是一个孤立标量公式，而是语义缺陷域、等价协议、分母治理、家族平衡和可审计解释的组合。

### RQ3：可控语义变异体与真实缺陷的一致性

> **RQ3：基于可控语义变异体得到的 MT 评价，能否预测或解释同一方法在开发者真实语义缺陷上的检测表现？**

核心分析包括：

- 同一 MT 方法在可控变异体与真实缺陷上的排序与效应方向；
- 项目级、算子家族级和语义缺陷类级的一致性；
- family-balanced SMS 与真实缺陷检测得分之间的关联；
- 可控变异体上的独有检测能否迁移到对应真实缺陷；
- `DIRECT`、`ADJACENT`、`OUT_OF_SCOPE`、`UNCERTAIN` 映射的分层结果；
- 现有算子体系无法表达的真实缺陷及其外部有效性含义。

主要一致性分析只使用预先冻结的 `DIRECT` 映射；`ADJACENT` 进入敏感性分析，`OUT_OF_SCOPE` 与 `UNCERTAIN` 保留但不强制映射。

## 4. 贡献层级

### C1：语义变异系统

提出一组跨项目抽象语义变异算子及其可控变异体生成、触发和认证机制。

### C2：等价处理与语义变异计分

提出证书优先的等价变异体协议，以及同时处理家族不平衡、等价性不确定性、trigger 和执行损耗的语义变异得分体系。

### C3：受控—真实双重验证

在冻结的公共项目框架和开发者真实 buggy/fixed 缺陷上，验证语义变异得分对 MT 完备性的区分能力，以及它与真实缺陷检测表现的一致性和边界。

### C4：可复现证据资产（次级）

提供内容寻址、角色隔离、结果盲化、append-only ledger 和 clean-room 复现工件。C4 支撑 C1–C3，但不与前三项等权，也不主导标题、摘要或结论。

## 5. B0/B1、元模式与 MR Family 的角色

### 5.1 定位

- `B0`：在不提供元模式、MR Family、D1 算子、D2 缺陷或检测结果的条件下生成的 LLM-native MR 集合；
- `B1`：按“公共接口 → 元模式 → MR Family → 项目 API 绑定 → 输入变换 → 关系 oracle”生成的结构化 MR 集合。

B0 与 B1 是用于检验语义变异系统**区分效度**的两个受控 MT 条件，不是 P3 的核心研究对象。比较必须保持模型、项目材料、seed、token、候选数、修复次数、执行预算和最终组合规模一致。

### 5.2 可允许的主张

若结果支持，可以说：

> 语义变异系统能够区分两个受控 MR 识别条件，并揭示其在不同语义算子家族和真实缺陷类上的互补与盲区。

不能把 P3 的中心主张改写为：

> 元模式或 MR Family 普遍优于 LLM-native MR 识别。

后者需要独立的 MR 识别方法论文、更广泛模型与提示变体以及专门的构念效度设计。

### 5.3 旧83个MR的处理

旧83个 MR 的生成时 provenance 审计用于说明为什么它们不能直接充当 B0。即使全部被确认为 `STRUCTURED_CONTAMINATED`，该结果也只适用于当前旧语料，不能外推为一般 LLM 或一般 MR 语料结论。

## 6. D1、D2、MR与P12在论文中的证据角色

| 轨道 | 论文角色 | 可支撑内容 | 不得支撑内容 |
|---|---|---|---|
| D1 | 算子归纳、校准与目标变异体生成 | RQ1、RQ2 的可控语义变异证据 | 真实缺陷总体表现 |

## 7. 核心预期结果

以下均为待检验预期，不是已观察事实。

### 7.1 语义变异系统有效

冻结算子能够在源不相交项目上稳定生成可构建、trigger 覆盖、确认非等价且具有预期语义分歧的变异体。

### 7.2 得分具有区分与解释能力

family-balanced SMS 能区分完备性不同的 MT 条件，并把差异定位到具体语义算子家族，而不是只给出一个由实例数量支配的总分。

### 7.3 可控评价与真实缺陷表现一致

在项目级、算子家族级或缺陷类别级，可控语义变异体上的评价与真实缺陷检测表现具有一致方向或可解释关联。

### 7.4 有价值的阴性结果

以下结果同样具有论文价值，不能因不利于某一方法而删除：

- 语义变异得分不能预测真实缺陷表现；
- 某些算子只在受控变异体上有效；
- 大量真实缺陷属于 `OUT_OF_SCOPE` 或 `UNCERTAIN`；
- family-balanced 与 instance-weighted 得出不同方法排序；
- 严格等价处理后原有优势缩小或消失；
- B0 与 B1 总体相当，但在不同语义家族上互补；
- 结构化方法提高覆盖，却带来可执行率或成本损失。

这类结果回答的是语义变异系统在何种条件下有效、为什么有效以及边界在哪里。

## 8. 非核心内容与降级位置

以下内容重要，但不得进入标题或前三项核心贡献：

- provider 数量、网关和模型接入；
- 跨厂商 LLM 审计；
- external human replication 的缺失或建议；
- P3/P12 双仓冻结和 tag 权限；
- clean-room、commitment、role policy 与 ledgers 的工程细节；
- B0/B1 prompt 模板和费用核算；
- held-out portfolio selection 或 DVE 策略优劣。

它们应分别进入 Experimental Controls、Baseline Construction、Reproducibility、Threats to Validity 或附录。只有当某项直接改变 C1–C3 的证据解释时，才在正文方法中展开。

## 9. 写作红线

1. 不把“计划可达”写成“算子已确认”。
2. 不把静态站点绑定写成有效变异体生成。
3. 不把构建失败、trigger 未覆盖或零 kill 写成等价。
4. 不把证书外的有限样本相等写成等价证明。
5. 不把 provider 或 workflow 就绪写成科学结果。
6. 不把旧83个 MR 的污染外推到一般 LLM。
7. 不把 B0/B1 比较升级为论文身份。
8. 不强制把所有真实缺陷映射到冻结算子体系。
9. 不把 D2 上的 selection-conditioned 检测率写成总体缺陷覆盖率。
10. 不在摘要、贡献或结论中使用 `blocked`、`insufficient` 或仅为计划状态的主张。

## 10. 当前主张状态基线

在确认性执行完成前，主张状态固定为：

| 主张 | 当前状态 | 允许措辞 |
|---|---|---|
| 已建立语义变异系统设计与治理协议 | `supported/qualified` | “我们预先规定了算子、等价与计分协议。” |
| 冻结算子能跨项目生成有效语义变异体 | `blocked` | “我们将检验冻结算子的跨项目生成有效性。” |
| 等价协议改善了得分稳健性 | `blocked` | “我们将比较严格、保守与家族平衡口径。” |
| SMS 能区分 MT 完备性 | `blocked` | “我们将检验 SMS 的区分效度。” |
| SMS 与真实缺陷检测一致 | `blocked` | “我们将检验受控—真实一致性。” |
| 结构化 MR 优于 native MR | `blocked` 且非核心 | “B0/B1 是两个受控评价条件。” |
